# TASK.md — Техническое задание: REST API на FastAPI

Реализовать REST API для учебного интернет-магазина.  
**Код реализации не предоставлен намеренно** — это тренировочное задание.

---

## Глобальные требования

### Версионирование
Все эндпоинты живут под префиксом `/api/v1/`.  
Исключение: `/health` — без префикса.

### Формат ошибок
Любая ошибка (4xx, 5xx) должна возвращать:
```json
{
  "error": {
    "code": "PRODUCT_NOT_FOUND",
    "message": "Product with id=42 not found",
    "details": []
  }
}
```
`details` — список объектов `{"field": "...", "msg": "..."}` для ошибок валидации (422).

### Пагинация (все list-эндпоинты)
Query-параметры:
| Параметр | Тип | По умолчанию | Ограничение |
|----------|-----|--------------|-------------|
| `limit`  | int | 20           | 1–100       |
| `offset` | int | 0            | >= 0        |

Ответ списка:
```json
{
  "total": 30000,
  "limit": 20,
  "offset": 0,
  "items": [...]
}
```

### Аутентификация
- JWT Bearer токены.
- **Access token**: TTL 15 минут.
- **Refresh token**: TTL 7 дней, хранится в httpOnly cookie или в теле — на выбор реализующего.
- Эндпоинты помечены: 🔓 (публичный), 🔑 (требует access token), 👑 (только admin).

### Ролевая модель
| Роль    | Описание                                      |
|---------|-----------------------------------------------|
| `user`  | Обычный пользователь, видит только свои данные|
| `admin` | Может читать и изменять данные любых пользователей |

### Наблюдаемость
- Каждый запрос принимает заголовок `X-Request-ID` (UUID). Если не передан — генерировать на сервере.
- Каждый ответ должен содержать заголовок `X-Request-ID` с тем же значением.
- Логировать: метод, путь, статус, время выполнения, X-Request-ID.

### Rate limiting
- Лимит: **100 запросов в минуту** на IP-адрес.
- При превышении: `429 Too Many Requests`.
- Обязательный заголовок в ответе: `Retry-After: <секунды до сброса>`.

### OpenAPI
Каждый эндпоинт должен иметь в схеме: `summary`, `description`, `response_model`, примеры запроса и ответа, все возможные коды ответов с описанием.

## 1. Auth

### POST /api/v1/auth/register 🔓
Регистрация нового пользователя.

**Body (JSON):**
| Поле       | Тип    | Обязательное | Правила                                     |
|------------|--------|--------------|---------------------------------------------|
| `email`    | string | да           | валидный email, уникальный                  |
| `username` | string | да           | 3–100 символов, только буквы/цифры/`_`, уникальный |
| `password` | string | да           | минимум 8 символов                          |

**Ответы:**
| Код | Условие                                      |
|-----|----------------------------------------------|
| 201 | Пользователь создан. Тело: `{id, email, username, role, created_at}` |
| 409 | Email или username уже занят                |
| 422 | Ошибка валидации полей                       |

---

### POST /api/v1/auth/login 🔓
Получение access + refresh токенов.

**Body (JSON):**
| Поле       | Тип    | Обязательное |
|------------|--------|--------------|
| `email`    | string | да           |
| `password` | string | да           |

**Ответы:**
| Код | Условие                                                 |
|-----|---------------------------------------------------------|
| 200 | `{access_token, token_type: "bearer", expires_in: 900}` |
| 401 | Неверный email или пароль                               |
| 422 | Ошибка валидации                                        |

> Пользователь с `deleted_at IS NOT NULL` должен получать 401, а не 200.

---

### POST /api/v1/auth/refresh 🔓
Обновление access токена по refresh токену.

**Body (JSON):**
| Поле            | Тип    | Обязательное |
|-----------------|--------|--------------|
| `refresh_token` | string | да           |

**Ответы:**
| Код | Условие                                        |
|-----|------------------------------------------------|
| 200 | `{access_token, token_type, expires_in}`       |
| 401 | Refresh токен невалиден или истёк              |

---

### POST /api/v1/auth/logout 🔑
Инвалидация refresh токена (занести в blacklist или удалить).

**Body (JSON):**
| Поле            | Тип    | Обязательное |
|-----------------|--------|--------------|
| `refresh_token` | string | да           |

**Ответы:**
| Код | Условие                       |
|-----|-------------------------------|
| 204 | Выход выполнен                |
| 401 | Access token отсутствует/истёк|

## 2. Users

### GET /api/v1/users 👑
Список всех пользователей.

**Query-параметры:**
| Параметр    | Тип    | Описание                           |
|-------------|--------|------------------------------------|
| `limit`     | int    | пагинация                          |
| `offset`    | int    | пагинация                          |
| `role`      | string | фильтр: `user` или `admin`         |
| `deleted`   | bool   | если `true` — только удалённые     |
| `sort`      | string | `created_at` (default) или `email` |
| `order`     | string | `asc` или `desc` (default: `desc`) |

**Ответы:**
| Код | Условие                                  |
|-----|------------------------------------------|
| 200 | Пагинированный список                    |
| 401 | Нет токена                               |
| 403 | Роль `user`                              |

> `deleted_at` включается в ответ для admins; для user — не показывать.

---

### GET /api/v1/users/me 🔑
Профиль текущего пользователя.

**Ответы:**
| Код | Условие       |
|-----|---------------|
| 200 | Данные юзера  |
| 401 | Нет токена    |

---

### GET /api/v1/users/{id} 🔑
Профиль пользователя по ID.

**Правило доступа:**
- `user` может получать только свой профиль → 403 на чужой.
- `admin` — любой.

**Ответы:**
| Код | Условие                          |
|-----|----------------------------------|
| 200 | Данные пользователя              |
| 401 | Нет токена                       |
| 403 | Нет прав (не владелец, не admin) |
| 404 | Пользователь не найден           |

---

### PATCH /api/v1/users/{id} 🔑
Частичное обновление профиля. `user` может менять только свой профиль.

**Body (JSON, все поля опциональны):**
| Поле       | Тип    | Правила                              |
|------------|--------|--------------------------------------|
| `username` | string | 3–100 символов, уникальный           |
| `password` | string | минимум 8 символов                   |

> Поле `email` и `role` менять через PATCH запрещено для роли `user` (403).  
> `admin` может менять `role`.

**Ответы:**
| Код | Условие                          |
|-----|----------------------------------|
| 200 | Обновлённый профиль              |
| 401 | Нет токена                       |
| 403 | Нет прав или попытка сменить роль|
| 404 | Пользователь не найден           |
| 409 | Username уже занят               |
| 422 | Ошибка валидации                 |

---

### DELETE /api/v1/users/{id} 🔑
Soft-delete пользователя (`deleted_at = NOW()`).  
`user` — только себя. `admin` — любого.

**Ответы:**
| Код | Условие                          |
|-----|----------------------------------|
| 204 | Успешно удалён (или уже был удалён — идемпотентно) |
| 401 | Нет токена                       |
| 403 | Нет прав                         |
| 404 | Пользователь не найден           |

## 4. Products

### GET /api/v1/products 🔓
Список товаров. Мягко удалённые (`deleted_at IS NOT NULL`) **не** показываются.

**Query-параметры:**
| Параметр      | Тип    | Описание                                              |
|---------------|--------|-------------------------------------------------------|
| `limit`       | int    | пагинация                                             |
| `offset`      | int    | пагинация                                             |
| `category_id` | int    | фильтр по категории (включая подкатегории)            |
| `price_min`   | float  | фильтр: цена от                                       |
| `price_max`   | float  | фильтр: цена до                                       |
| `in_stock`    | bool   | если `true` — только stock > 0                        |
| `sort`        | string | `price`, `created_at`, `name` (default: `created_at`) |
| `order`       | string | `asc` или `desc` (default: `desc`)                    |
| `q`           | string | поиск по name (ILIKE `%q%`)                           |

**Ответы:** 200 — пагинированный список, 422 при невалидных параметрах.

---

### GET /api/v1/products/{id} 🔓
Если `deleted_at IS NOT NULL` — вернуть 404.

**Ответы:** 200, 404.

---

### POST /api/v1/products 👑

**Body (JSON):**
| Поле          | Тип    | Обязательное | Правила                    |
|---------------|--------|--------------|----------------------------|
| `category_id` | int    | да           | категория должна существовать |
| `name`        | string | да           | 2–255 символов             |
| `description` | string | нет          | максимум 5000 символов     |
| `price`       | float  | да           | >= 0                       |
| `stock`       | int    | нет          | >= 0, по умолчанию 0       |

**Ответы:** 201, 401, 403, 404 (category_id), 422.

---

### PUT /api/v1/products/{id} 👑
Полная замена. Все поля обязательны кроме `description`.  
Требует заголовок `If-Match: <version>` для optimistic locking.

**Заголовок:**
```
If-Match: 3
```
Значение должно совпадать с текущим `version` в БД. При несовпадении → 409.  
После успешного обновления `version` инкрементируется на 1.

**Ответы:**
| Код | Условие                                         |
|-----|-------------------------------------------------|
| 200 | Продукт обновлён. Заголовок `ETag: <new_version>` |
| 401 | Нет токена                                      |
| 403 | Роль `user`                                     |
| 404 | Продукт не найден или удалён                    |
| 409 | `If-Match` не совпал с `version` (конфликт)     |
| 422 | Ошибка валидации                                |
| 428 | Заголовок `If-Match` отсутствует                |

---

### PATCH /api/v1/products/{id} 👑
Частичное обновление. Заголовок `If-Match` **не** требуется (только для PUT).

**Body (JSON, все опциональны):** `name`, `description`, `price`, `stock`, `category_id`.

**Ответы:** 200, 401, 403, 404, 422.

---

### DELETE /api/v1/products/{id} 👑
Soft-delete (`deleted_at = NOW()`). Идемпотентен: повторный DELETE уже удалённого → 204.

**Ответы:** 204, 401, 403, 404.

## 5. Orders

### GET /api/v1/orders 🔑
- `user`: только свои заказы.
- `admin`: все заказы.

**Query-параметры:**
| Параметр    | Тип    | Описание                                                     |
|-------------|--------|--------------------------------------------------------------|
| `limit`     | int    |                                                              |
| `offset`    | int    |                                                              |
| `status`    | string | фильтр по статусу: `pending`, `confirmed`, `shipped`, `delivered`, `cancelled` |
| `user_id`   | int    | только для admin                                             |
| `sort`      | string | `created_at` (default), `total_amount`                       |
| `order`     | string | `asc` / `desc`                                               |

**Ответы:** 200, 401.

---

### GET /api/v1/orders/{id} 🔑
Включает вложенный список `items` (массив order_items с данными продукта).  
`user` видит только свой заказ, иначе 403.

**Ответы:** 200, 401, 403, 404.

---

### POST /api/v1/orders 🔑
Создание заказа. **Требует заголовок `Idempotency-Key`** (UUID v4).

#### Протокол Idempotency-Key:
1. Сервер ищет `key` в таблице `idempotency_keys` для данного `user_id`.
2. Если запись найдена и не истекла (`expires_at > NOW()`):  
   - вернуть сохранённый `response_status` и `response_body` **без** повторного выполнения.
3. Если записи нет или она истекла — выполнить запрос как новый:
   - Сохранить `key`, `user_id`, код и тело ответа в `idempotency_keys`.
   - TTL: `expires_at = NOW() + 24 hours`.
4. При гонке двух одновременных запросов с одним ключом → один получает 201, второй 409.

#### Транзакция создания заказа:
Выполняется в одной транзакции:
1. Создать запись в `orders`.
2. Для каждого элемента `items`:
   - Проверить, что `product_id` существует и не удалён.
   - Проверить, что `stock >= quantity` (если нет → откат и 409).
   - Уменьшить `stock` на `quantity` (`UPDATE products SET stock = stock - qty WHERE id = ...`).
   - Создать запись `order_items` с `price_at_purchase = products.price` на момент транзакции.
3. Обновить `total_amount` в `orders`.

**Body (JSON):**
```json
{
  "items": [
    {"product_id": 1, "quantity": 2},
    {"product_id": 5, "quantity": 1}
  ]
}
```

| Поле             | Тип   | Обязательное | Правила                              |
|------------------|-------|--------------|--------------------------------------|
| `items`          | array | да           | минимум 1 элемент, максимум 50       |
| `items[].product_id` | int | да         | должен существовать, не быть удалён  |
| `items[].quantity`   | int | да         | >= 1                                 |

**Ответы:**
| Код | Условие                                                  |
|-----|----------------------------------------------------------|
| 201 | Заказ создан. Тело: полный объект заказа с items         |
| 400 | Отсутствует заголовок `Idempotency-Key`                  |
| 401 | Нет токена                                               |
| 409 | Недостаточно товара на складе, или гонка по idempotency  |
| 422 | Ошибка валидации items                                   |

---

### PATCH /api/v1/orders/{id} 🔑
Изменение статуса заказа.

**Допустимые переходы статуса:**
```
pending → confirmed → shipped → delivered
pending → cancelled
confirmed → cancelled
```
Обратные переходы и прыжки через состояния запрещены → 422.

`user` может только отменить свой заказ (`cancelled`).  
`admin` может делать любой допустимый переход.

**Body (JSON):**
```json
{"status": "confirmed"}
```

**Ответы:** 200, 401, 403, 404, 422.

---

### DELETE /api/v1/orders/{id} 🔑
Отмена заказа (эквивалент PATCH status=cancelled).  
`user` — только свой. Заказ в статусе `shipped` или `delivered` — 422.

**Ответы:**
| Код | Условие                                     |
|-----|---------------------------------------------|
| 204 | Заказ отменён                               |
| 401 | Нет токена                                  |
| 403 | Чужой заказ                                 |
| 404 | Заказ не найден                             |
| 422 | Статус `shipped` или `delivered` — нельзя отменить |

## 6. Order Items

Список позиций заказа. Включает данные продукта (`product_id`, `name`, `price`).

- Пересчитать разницу и скорректировать `stock` в `products`.
- Пересчитать `total_amount` в `orders`.

**Ответы:**
| Код | Условие                                    |
|-----|--------------------------------------------|
| 200 | Обновлённая позиция                        |
| 401 | Нет токена                                 |
| 403 | Чужой заказ                                |
| 404 | Заказ или позиция не найдены               |
| 409 | Недостаточно товара на складе              |
| 422 | Статус заказа != `pending`                 |

## Дополнительные требования к реализации

### Транзакции
- `POST /orders` — обязательно всё в одной транзакции (orders + order_items + stock).
- Если любой из товаров не прошёл проверку stock — откат всей транзакции.

### Optimistic locking (products)
- `PUT /products/{id}` требует заголовок `If-Match: <version>`.
- В транзакции: `UPDATE products SET ... WHERE id = ? AND version = ?`, проверить `rowcount`.
- Если `rowcount == 0` — вернуть 409.
- После успешного обновления: `version += 1`.

### Idempotency (orders)
- Таблица `idempotency_keys` должна иметь `UNIQUE(key, user_id)` или PRIMARY KEY по `key`.
- При гонке двух запросов: использовать `INSERT ... ON CONFLICT DO NOTHING` и проверять результат.
- Фоновая задача или TTL-based cleanup не требуется в рамках тренировки, но `expires_at` индексируется.

### Статусные переходы заказа (машина состояний)
```
pending ──→ confirmed ──→ shipped ──→ delivered
   └──→ cancelled       ↑
confirmed ──────────────┘  
```
Любой другой переход → 422 с описанием допустимых.

### PUT vs PATCH (общее правило)
- **PUT**: тело должно содержать **все** поля ресурса. Отсутствующие необязательные поля устанавливаются в `null`/default. Это полная замена.
- **PATCH**: тело содержит **только** изменяемые поля. Отсутствующие поля остаются без изменений.

### DELETE — идемпотентность

| orders           | 404             | физическое (не реализуется как soft) |
| reviews          | 404             | физическое удаление          |
